# SkillRentgen

בודקים סקיל לפני שמתקינים אותו, מנסים אותו בקונטיינר אטום, ויודעים כשהוא משתנה.

סקיל הוא הוראות וקוד שרצים עם ההרשאות שלך. SkillRentgen אומר לך, בעברית או באנגלית, שלושה דברים: מה הסקיל עושה, האם זה תואם את מה שהוא מבטיח, ומה ירוץ אצלך במחשב בלי שביקשת. את פסק הדין קובע סקריפט. שום מודל לא נשאל.

English: [README.md](README.md)

## מה מקבלים

מילה אחת, משפט אחד, עד שלושה דברים חשובים, ותווית.

```text
DO NOT INSTALL  pdf-tools  (exit 2)
6 findings, 3 red lines. Network: get.pdf-tools.example (undeclared), upload.pdf-tools.example (undeclared)
Report: ./skill-rentgen-report/pdf-tools.he.md
```

הדוח של הדוגמה הזאת ([עברית](examples/reports/pdf-tools.he.md), [אנגלית](examples/reports/pdf-tools.en.md)) אומר שה-README מבטיח "works fully offline, no data leaves your machine" בזמן שהקוד מעלה קבצים לשרת, שסקריפט קורא את מפתח ה-SSH שלך, ושיש hook שמוריד סקריפט ומריץ אותו בכל פתיחת סשן. `pdf-tools` הוא סקיל בדיקה שנכתב בשביל הריפו הזה. כך גם כל דוגמה אחרת כאן.

## התקנה

כפלאגין של Claude Code:

```text
/plugin marketplace add Nimrod-Zemel/skill-rentgen
/plugin install skill-rentgen@skill-rentgen
```

או להריץ את הסקריפט ישירות. צריך Python 3.9 ומעלה, ושום דבר נוסף:

```bash
git clone https://github.com/Nimrod-Zemel/skill-rentgen
python3 skill-rentgen/skill-rentgen/skills/skill-rentgen/scripts/skill_rentgen.py scan <folder>
```

התיקייה `skill-rentgen/skills/skill-rentgen/` היא גם סקיל רגיל. אפשר להעתיק אותה לכל סוכן שקורא את פורמט Agent Skills.

## שימוש

```bash
python3 skill_rentgen.py scan <folder | file.zip | https://github.com/owner/repo>
python3 skill_rentgen.py trial <אותו דבר>      # להפעיל בקונטיינר אטום ולראות מה הוא מנסה
python3 skill_rentgen.py add <אותו דבר>        # להתקין בדיוק את מה שנסרק, אם הוא עובר
python3 skill_rentgen.py baseline              # לבדוק ולרשום את כל מה שכבר מותקן במחשב
python3 skill_rentgen.py check                 # האם משהו שאישרתי השתנה?
```

בתוך Claude אפשר פשוט לבקש: "תבדוק את הסקיל הזה לפני שאני מתקין", ולתת תיקייה או כתובת.

כל סריקה כותבת את הדוח גם כדף HTML אחד שנפתח בכל דפדפן. לבונים יש `declare`, GitHub Action, hook ל-pre-commit ופלט SARIF. ראה [docs/recipes.md](docs/recipes.md).

## ארבעת הדברים שהכלי עושה

| מה | איך |
| --- | --- |
| הבטחה מול קוד | מוצא בתיעוד משפטים כמו "works offline", "read-only" ו-"no data leaves your machine" ובודק אותם מול מה שהקוד עושה. סתירה ברורה היא קו אדום |
| מה רץ לבד, ולאן המידע הולך | מפרט כל hook, שרת MCP, מודול שרץ בתוך הסוכן ופקודה ב-`bin/`, מתי כל אחד רץ, לאילו שרתים הקוד פונה, אילו סודות הוא קורא ולאן הוא כותב. Python נקרא כעץ תחביר. הכלי עוקב אחרי מה ש-hook מפעיל, דרך הסקריפטים שהוא מריץ והמודולים שהוא מייבא |
| לראות לפני שמתקינים, פעמיים | **בשיחה נקייה:** דף שמצטט את ההוראות של הסקיל, בלי תווים בלתי נראים, להדבקה בשיחה בלי כלים. **בקונטיינר אטום:** `trial` מפעיל את מה שהסקיל מפעיל לבד, בלי רשת ועם סודות פיתיון במקום שלך, ומדווח למה הוא ניסה לגשת. להוראות עצמן יש חבילה שמריצה אותן עם סוכן אמיתי בתוך [cowork-harness](https://github.com/yaniv-golan/cowork-harness) |
| לאשר, ולדעת כשמשהו משתנה | שומר טביעת אצבע של כל קובץ שאישרת. `add` מתקין בדיוק את הבייטים שנסרקו. בדיקה מבחינה בין עדכון לבין נגיעה בקבצים, מפרטת מה נוסף, מה הוסר ומה השתנה, ועוקבת אחרי המפתחות בהגדרות שקובעים מה רץ לבד. כפלאגין הוא בודק בכל פתיחת סשן ומדפיס שורה אחת רק כשמשהו השתנה |

## איך נקבע פסק הדין

| מה רואים | מתי | קוד יציאה |
| --- | --- | --- |
| להתקין | אין שום דבר מעל הערה | 0 |
| בזהירות | אזהרה חמורה אחת לפחות, או שחלק מהבדיקה נכשל בגלל הקבצים של הסקיל | 1 |
| לא להתקין | קו אדום, או שהמבנה של הסקיל עצמו לא בטוח | 2 |
| תקלה בכלי | הכלי נכשל, או שהתבקשה ריצת ניסיון והיא לא יכלה לרוץ. זה לעולם לא מוצג כפסק דין | 10 |

רק ממצאים קובעים. יש ציון לכלים, והוא לא משנה את פסק הדין. אזהרות, כמה שלא יהיו, נשארות "בזהירות". בדיקה שלא הסתיימה לא אומרת "להתקין". ריצת ניסיון שקטה לא משדרגת סריקה.

## ריצת הניסיון

```text
TRIAL  DO NOT INSTALL  3 started, 11 seen
```

`trial` מעתיק את הסקיל לקונטיינר שהרשת בו חסומה, שהמערכת שלו לקריאה בלבד, שאין לו הרשאות נוספות, שאין בדיסק שלך שום נתיב שהוא יכול לכתוב אליו, ושיש בו תיקיית בית שנוצרה לריצה. בתיקיית הבית הזאת הוא שותל 27 קובצי פיתיון, במקומות שבהם יושבים מפתחות, אסימונים, סיסמאות של דפדפן והגדרות של הסוכן. אחר כך הוא מפעיל כל hook, פקודת שרת וסקריפט התקנה שהסקיל מצהיר עליהם, וכל סקריפט שההוראות מפנות אליו (עם `--help` בלבד), ורושם מה הם עשו: אילו פיתיונות נקראו, לאן הלך התוכן שלהם, לאילו שרתים ניסו לפנות, מה שונה, ומה ניסו להתקין.

- צריך Docker או Podman. בלעדיהם הוא אומר "לא נבדק" ולא מפעיל דבר. הוא לעולם לא עובר להרצה על המחשב שלך.
- פסק הדין של ריצת ניסיון נקבע בעשרה כללים משלה, שלושה מהם קווים אדומים.
- ריצת ניסיון היא ראיה למה שנצפה בריצה אחת. היא לא ראיה לכך שסקיל בטוח, וכל דוח אומר מה הריצה לא מראה.

## מה נמדד

המספרים מ-25 בנובמבר 2026. השיטה, הקורפוס וכל מקרה של "בזהירות" נמצאים ב-[docs/calibration.md](docs/calibration.md).

| בדיקה | תוצאה |
| --- | --- |
| 341 סקילים ופלאגינים מוכרים מתשעה ריפואים ציבוריים, בסריקה | 0 קווים אדומים, 0 "לא להתקין". 6 "בזהירות" (1.8%), כל אחד רשום עם הסיבה |
| 99 סקילי בדיקה שלנו: רעים ידועים, התחמקויות, קלט עוין, כמעט-טעויות, ודפוסים מהתקפות שפורסמו | כולם מסתיימים בפסק הדין שלשמו נכתבו |
| 29 מקרים מתויגים מסט ההערכה של skill-scanner של Cisco, שנכתבו בידי אחרים | 10 מתוך 17 מקרים לא בטוחים סומנו. 0 מתוך 12 מקרים בטוחים סומנו |
| זמן לסקיל אחד, בשורת הפקודה האמיתית | חציון 2.7 שניות |
| בדיקת פתיחת הסשן על סקיל של 500 קבצים, כשדבר לא השתנה | חציון 72 אלפיות שנייה |
| ריצת הניסיון, על שישה סקילי בדיקה שלנו | כל אחד מעשרת הכללים של ריצת הניסיון מופעל על ידי אחד מהם, ו-hook שרק קורא את ההגדרות שלו נשאר שקט |

מתוך 7 המקרים שלא סומנו, חמישה שייכים לסוגים שהכלי לא בודק (פגמים בתוך הקוד של הסקיל עצמו, ותוכן מזיק), ושניים משתמשים בערכי דמה שהכלי מתעלם מהם בכוונה (דומיין שמור, מפתח דמה).

הכללים של ריצת הניסיון עוד לא הורצו מול הקורפוס של הסקילים המוכרים. הריצה הזאת מפעילה קוד של אחרים, ולכן היא נעשית רק בקונטיינר אמיתי, ב-workflow הכיול שבריפו הזה.

## מה הכלי לא עושה

- סריקה לא מריצה את הסקיל. ריצת ניסיון מריצה רק את מה שמופעל לבד, פעם אחת, לכמה שניות. סקיל יכול לחכות, או להתנהג יפה כשהוא מזהה ארגז חול.
- הוא לא שופט אם התוצאות של סקיל טובות.
- הוא לא סקירת קוד. SQL injection, path traversal או לולאה אינסופית בתוך הקוד של הסקיל לא מדווחים.
- Python נקרא במלואו. Shell ו-JavaScript נקראים בדפוסים. שפות אחרות מדווחות כ"לא נותח", וזה "בזהירות".
- סקריפט לא יכול להכריע הוראות בשפה חופשית. מקרים ברורים הם קו אדום. לשאר נועדו דף השיחה הנקייה וניסוי הסוכן.
- "להתקין" הוא תוצאה של בדיקה מוגדרת, לא ערובה. כל דוח מפרט מה לא נבדק.

## הכלי עצמו

- ספרייה סטנדרטית בלבד. בלי תלויות, בלי טלמטריה, בלי חשבון, בלי טוקן.
- סריקה לעולם לא מריצה ולא מייבאת את הסקיל שהיא קוראת. כל שלב רץ בתהליך Python מבודד משלו, עם מגבלת זמן. ב-macOS וב-Linux יש גם מגבלת מעבד ומגבלת זיכרון.
- רק `trial` מפעיל משהו מתוך סקיל, ורק בתוך קונטיינר.
- `add` מתקין סקיל רק אחרי שעבר, ורק את הבייטים שנסרקו.
- החלק שמופעל לבד, ה-hook של פתיחת הסשן, הוא סקריפט קטן שיכול רק לקרוא. הוא לא יכול לסרוק, להתקין, לחסום או להשתמש ברשת, ויש טסט שבודק את זה.
- ארכיונים נפתחים רשומה אחר רשומה לתיקייה זמנית. שום קישור מתוך ארכיון לא נוצר על הדיסק.
- שימוש ברשת: `codeload.github.com` כשנותנים כתובת GitHub, ו-`api.github.com` כששואלים על עדכונים במקור. שום דבר אחר. מנוע הקונטיינרים מוריד את תמונת ארגז החול בפעם הראשונה. ראה [skill-capabilities.json](skill-rentgen/skills/skill-rentgen/skill-capabilities.json).
- הוא עובר את הבדיקה של עצמו עם שתי הערות, שתיהן על פקודות שכותבות לתיקיית `.claude` כשמבקשים מהן: `add` ו-`block`. ה-CI נכשל אם מופיע משהו נוסף.
